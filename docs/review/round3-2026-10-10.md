## Remaining: BUG (unfixed — needs a decision or larger change)

1. **ML recovery-model subsystem is non-functional end-to-end** (`feature_engineering.py`, `main.py:536-592`, `recovery_model.py`)
   - `SELECT * FROM activity_metrics` has no `start_date` → activity join silently skipped → model trains on ~7 of 29 features.
   - Prediction path provably dead: single-day frame → rolling z-scores NaN → `dropna(thresh=14)` drops the row → `ml_prediction` always None. Model is retrained from scratch every 15 min and never predicts.
   - Target is next-day RHR (bpm) but exposed as `predicted_prs` (0–10) and clipped to (0,120).
   - Fix: JOIN for `start_date` (as the readiness path does), pin the feature list, pick one target, use `partial_fit` or stop loading before retrain.

2. **Prescription-engine safety guardrails are dead code** (`main.py:719-728`, `prescription_engine.py`)
   - `PrescriptionInput` never gets pain/soreness/sleep/stress/PRS → pain veto, edge-case overrides, sleep-debt + overshoot guardrails can never fire; Subjective index always 0; confidence always "low".
   - Morning check-ins **are collected** by the dashboard (`morning_checkin` table) but `main.py:543` passes `morning_checkins=None` and `store.get_morning_checkins` has zero callers.
   - Engine output (`safety_notes`, `daily_plan`) is stored in `analysis["prescription_engine"]` but rendered nowhere — the LLM that writes `today_prescription.txt` never sees it.
   - Fix: wire today's check-in into `PrescriptionInput`, add perceived-readiness/pain fields to the check-in form, render safety notes into the prompt.

3. **weekly_planner ignores readiness** (`weekly_planner.py:579,623`)
   - `session_pattern = ["endurance","threshold","vo2"]` applied unconditionally; `day_readiness` computed but unused; the readiness-aware `_select_session_type` (downgrades below 40/55) is dead code.
   - `validate_plan` correctly rejects threshold/VO2 at readiness < 60 but `generate_weekly_plan` only logs the failure and ships the plan.
   - Fix: call `_select_session_type`; downgrade offending days on validation failure.

4. **Model JSON save/load schema drift** (`individual_model.py:283-330`, `recovery_model.py:340-378`)
   - `feature_names` saved in canonical order, `model_coef` in pandas column order — the two differ; `get_feature_importance` mislabels; data-dependent correlation pruning can silently misalign coefficients on load.
   - Fix: persist the exact fitted column order (or reorder X to `feature_names`), assert lengths on load, pin the feature set.

5. **Dashboard TSB-floor safety setting silently discarded** (`visualize.py:1739-1743` vs save template 1788-1818)
   - Slider sets `profile["tsb_floor"]` but the save template has no such line → `weekly_planner.py:345` always gets the default −10.
   - Related: `max_session_duration` parse silently falls back to 90 for "1.5 hours."

6. **readiness.py ACWR systematically biased** (`readiness.py:444-460`)
   - 32-day TSS window with 18/7-day half-lives starting from 0 → residual weight on the zero seed ≈ 0.30 → CTL underestimated up to ~30%, ACWR overestimated up to ~40% vs the full-history values in `training_load.py` (two different ACWRs in the same `latest_analysis.json`).

7. **Concurrency bugs in tasks/** (`worker.py`, `scheduler.py`)
   - Cancel during activity phase is overwritten by `mark_completed`; analyze/prescribe still run after cancel.
   - Scheduler interval changes never apply to the running loop (captured once at start).
   - Enabling auto-sync triggers a double initial sync (4 API calls, 2 concurrent).
   - `start()` double-start race (status set after thread spawn).
   - `stop()` orphans a running sync thread; a second loop can start.

8. **setup.py credential/cron flow** (4 bugs)
   - Writes PBKDF2 hash **without** the `_RAW` companion → re-running setup permanently breaks Garmin auth (hash submitted as password → circuit breaker pauses sync).
   - Pressing Enter at the password prompt wipes the existing credential.
   - Cron prompt says "05:00 each morning" but installs the every-15-min backfill job (missing `--daily`).
   - `setup_garmin()` reads `os.getenv` instead of the just-written env → API-sync branch dead in the same run.
   - Also: no `chmod 600` on the config.env it creates.

## Remaining: RISK

9. **Plaintext Garmin password in config.env** — `GARMIN_PASSWORD` plaintext (file now 600); the "hashed" path stores `GARMIN_PASSWORD_RAW` plaintext alongside the hash, and `_resolve_hashed_passwords` silently skips (no warning) when `_RAW` is missing. Migrate to hashed form via UI sign-in and decide whether RAW persistence is acceptable.
10. **`sync_to_ha.py`** — hardcoded `HA_PASS`; full-vault SMB upload every run (config.env, llm_config.json, 3.7 GB DB) with no incremental sync, no size/timeout guard; sqlite copied while writers active (WAL skipped, main DB may be mid-write); `pysmb` not in requirements/venv (script can't run as-is); file handle not closed on exception.
11. **`llm_config.json`** — LLM API key in plaintext at umask perms; swept into the SMB upload. chmod 600 on save.
12. **DB concurrency & growth** — no `busy_timeout` (default 5 s) with cron + Streamlit both writing; `refresh_activities` and `store_activity_streams` hold single write transactions over 1k–100k+ rows; `run_analyze` `fetchall()`s all 20.6 M `activity_streams` rows into memory every 15-min run (~6–8 GB transient); no retention policy (streams 20.6 M rows, routes 7.3 M, DB 3.7 GB and growing); `sync_garmin`/`sync_activities` leak DB connections on error paths (no try/finally); wellness upsert overwrites stored values with NULL on partial re-fetch.
13. **`latest_analysis.json`** written non-atomically by two processes (cron + dashboard sync); dashboard `_save_readiness_explanation` does an unlocked read-modify-write. Use temp-file + `os.replace`.
14. **LLM client** — no retry backoff, 5xx not retried; wiki ingest makes 2 sequential blocking calls in the UI thread (worst case ~12 min frozen UI); conversation serialization re-parses `USER:`/`ASSISTANT:` lines inside message content (self-injection surface).
15. **Dockerfile** runs as root (no `USER`).
16. **README "zero secrets" claim is false** — `git add -f .` would commit `sync_to_ha.py` with the hardcoded HA password.
17. **Tests**: 3 files re-implement the code under test (vacuous coverage: `test_wellness_sync` date-format loop, `test_fit_parsing` extraction copy, `test_data_persistence` run.sh copy); 11 fixture files use a `morning_checkin` schema that doesn't match production DDL; 10 AppTest files clobber process env without save/restore; zero coverage for the login circuit breaker, `db_query`, `scheduler`, sync_state corruption.
18. **requirements**: loose `>=` pins, byte-identical duplicate files, CI on Python 3.12 vs local 3.14.
